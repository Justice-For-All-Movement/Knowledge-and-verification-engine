# Captured exact-span proposal acceptance (partial AM-05.04)

`acceptCapturedClaimProposal` (`./proposal-acceptance`) is a pure transition over host-supplied Knowledge/citation histories and an inspected captured proposal bundle. It selects one explicit proposal and requires the complete containing history counts, exact latest parent claim/citation editions, selector/fingerprint/relation and valid Unicode excerpt. A fresh claim ID is mandatory. It returns detached appended Knowledge and citation histories plus a private acceptance record; it performs no SQL, network, authentication or external policy call. Input histories are unchanged on failure. Existing history budgets fail the whole transition rather than evicting history.

The result is an unassessed private research inference with unknown time and no inferred subjects. Assessment, procedural posture and editorial approval remain null. The complete original selector, source hash/ref, representation identity/digest, fingerprint and family metadata are preserved in the new citation. The absolute UTF16 excerpt remains separate in the acceptance record. The parent's supports/challenges relation is historical metadata only: the new claim receives a **quotes** link, never automatic support or corroboration for a different assertion.

This pure profile does not authenticate context, bundle digest, source bytes, current permissions or accepted assertion text. Recomputing the bundle digest can change its untrusted assertion; an explicit regression preserves that boundary. The acceptance record is domain metadata, not a persisted audit event or a credential. `capturedEvidenceRevision` remains supplied observation metadata, not an independent current observation. New claim/citation refs are unpersisted until an authorized owning repository commits both histories and the acceptance record atomically.
