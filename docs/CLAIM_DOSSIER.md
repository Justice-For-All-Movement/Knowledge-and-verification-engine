# Captured private claim dossier (partial AM-05.07)

createCapturedClaimDossier(context,captureJson,{claim,links}) is a pure metadata assembler for an independently host-authorized human researcher/owner. The JSON text must contain exactly {knowledge,links}, holding complete private Knowledge and citation histories. It selects exact latest claim/citation editions within those supplied histories, validates all history/lineage via the existing domain inspectors and retains the entire citation record: supports, challenges, quotations, exact selectors/digests, family roots/fingerprints and original record metadata. All earlier challenges for this logical claim are retained separately with their exact historical citation-set/claim refs, even if a later set removes them. Repeated historical observations are not independent corroboration. An empty current citation set remains visibly empty and never erases those historical challenges or proves absence. Included subject/historical citation purposes must match the fixed report purpose.

The returned private structured table preserves the literal unassessed claim, all limitations/null assessment/procedural/editorial tracks and exact subject records. Each subject retains its selected historical edition plus the latest edition observed in the supplied history and an explicit same-edition/changed-in-capture status. A corrected date is visible without replacing the original subject or declaring truth, invalidating a decision or closing an investigation. Record counts describe supplied logical histories, never storage revisions, creation editions or completeness proof. No actor/time/audit is synthesized.

Ingress is JSON text bounded to5MiB UTF8; output is bounded as a complete canonical object to512KiB. Oversize reports fail wholly; contrary material is never truncated. Returned values are detached. Literal strings are data; the structured table is not HTML. Any later renderer must escape or use textContent. Duplicate JSON keys follow native JSON parsing; this profile does not authenticate original input bytes. Host CPU/heap/ingress limits remain required.

This is a captured metadata profile, not a current authenticated service or export route. Context/captures/selector fingerprints are not authentication, source-byte/scanner proof, Consent/Identity permission, independence counts, verification work, findings, answers or publication authority. Evidence bytes, current source permissions, verification reviews and raw audit events are explicitly unloaded. Current protected read/Consent/Evidence services and private export authorization remain mandatory before an operational use; copied data cannot be revoked. No SQL, credentials, provider/network calls, persistence, automatic revisions or delivery are added.
