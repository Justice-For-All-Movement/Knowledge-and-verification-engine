# Source-backed private link writes — partial AM-05.02

SourceEvidenceLinksWriter (./source-links) accepts only authenticated host Context, expected owning link storage revision, exact claim/link command, command ID and optional cancellation signal. It captures input and strips incoming roles, performs a current Identity/owning Knowledge admission read, obtains a host-authorized human/delegated Evidence credential, and calls the configured actual EvidenceService.captureSelectorLinks once for nonempty links. It checks complete bounded scope/purpose/schema/positive source edition/count/exact selector/family/fingerprint bindings, then freshly resolves current Knowledge Identity before the owning SQL operation. No caller EvidenceState or source analysis is accepted, and no authorized full source snapshot is fabricated. Existing APIs remain unchanged; hosts select this path explicitly, without snapshot fallback on denial or uncertainty.

The owning Knowledge project lock precedes actual current Knowledge and link history reads, command cache lookup and storage CAS. New writes validate the exact current stored claim, expected logical link edition, predecessor, unique IDs/relation/selectors, scope/purpose/private history limits and complete compact capture. One immutable link revision, containing storage revision, recorded audit, effect outbox and command acknowledgement commit together. Source metadata remains exact captured family snapshots/fingerprints; the recorded audit retains the actual observed Evidence aggregate revision (null for explicit empty links), alongside observed Knowledge revision. It invents no Identity policy edition. Empty link sets require capture:null and no credential/Evidence request; they do not prove evidence absence or completeness. Support/challenge/quote labels remain literal authored relationships, not verified findings. Combined source analysis returned by capture is deliberately unused/not persisted; accepted current review still analyzes each relation separately.

The pure reviseEvidenceLinksFromCapture and low-level recordCapturedEvidenceLinks APIs accept host-trusted typed captures; object syntax/digests are NOT authentication. Only the configured owning-service composition supplies source provenance. Host must authorize credential release per human or explicit delegation using trusted proofing/current policy/vault mapping. This adapter does not inspect token identity or establish that Evidence token principal equals Knowledge principal. Credential roles are not accepted from caller input, and credentials never enter Knowledge SQL/audits/results. Production adapters never use Evidence SQL/object roots; each engine has its own database.

The whole operation uses a default10s monotonic acceptance budget configurable1..30000ms. Credential callbacks are raced against cancellation; begun Identity/Knowledge/Evidence SQL is awaited. Source result copies and binding checks are gated. A trusted admission callback is propagated to the owning repository and sampled after locked reads before cache lookup and before a new domain put, so a lock wait or blocked JS cannot silently admit a late command. Low-level host callers may supply that callback; it is admission discipline, not authentication. Once write SQL begins, its acknowledged result remains acknowledged even after cancellation/deadline. SQL may outlive the budget; failed COMMIT acknowledgement is UNKNOWN, not rollback, and requires explicit later reauthorization/replay. Callbacks/signals close on exit. CPU/heap/driver/transaction/concurrency limits remain mandatory; this is not process isolation or SQL termination.

New capture commands use a distinct operation fingerprint from legacy snapshot writes. Capture metadata is intentionally excluded from idempotency fingerprints. Every coordinator invocation reloads current authority and (for nonempty links) captures currently usable source metadata, including replay. The cached result is only original historical storage/record refs; it never revalidates old records as current source/claim truth, issues a new effect or becomes an execution permit. Another new command may change later link history without rewriting that historical acknowledgement. Direct low-level host APIs remain host-trust paths and must not be exposed as authenticated endpoints.
