prepareEvidenceReview reads actual owning Knowledge and link histories together under the Knowledge project lock and returns containing revisions plus the exact latest link set after current-claim/purpose validation. The coordinator loads that basis, calls the configured authenticated Evidence service separately for supports/challenges/quotes, compares returned selectors/fingerprints to the captured links and requires one identical observed Evidence aggregate revision across nonempty relation groups. Sources from different relations never inflate one another. Empty relations return null (no Evidence observation); an entirely empty link set performs only checked Knowledge reads and reports evidenceRevision:null. Unknown families remain unresolved. It reloads the basis through current Identity after source work and denies any changed Knowledge or link storage edition. All returned records are detached. This creates checked read audits only, not new domain records, outbox effects, persisted assessment or cached permission.

The constructor captures receivers, a trusted EvidenceCredential callback and a default10s acceptance budget configurable1..30000ms. Callback receives copied Context with incoming roles stripped and an owned AbortSignal. It must release a current credential authorized for that human or an explicitly authorized delegation, using trusted identity/policy/vault mapping. Arbitrary caller roles or possession of a general service token are not credential-release policy. Credential issuance/proofing and delegated audience mapping are host responsibilities; this adapter does not inspect token identity or assert the Evidence principal equals the Knowledge principal. Evidence independently authenticates its credential/scope/purpose; Knowledge independently enforces current membership/resource authority. No credentials enter Knowledge SQL/audits/results.

A full monotonic deadline/cancellation gate applies before/after callbacks, SQL, copied results and return. The credential callback is cancellable/raced; begun Identity/Knowledge/Evidence SQL is awaited, and acceptance can remain pending until the driver settles. Deadlines do not terminate SQL, preempt blocked JS, undo callback work or prove rollback. Every owned signal closes. Lost checked-read COMMIT acknowledgement is unknown and a later explicit review must reauthorize. There is no automatic retry or snapshot fallback. Host driver, identity directory and process CPU/heap limits remain mandatory.

Result checks bind scope/purpose/profile/positive containing revision, exact selectors/fingerprints, bounded selected-reference source partitions and output budgets (256KiB/source observation,512KiB/final review). Evidence itself enforces its64-selector/64KiB request and bounded stored graph. Large formerly captured links can therefore fail this path. Fingerprint mismatch requires explicit link revision; it never rewrites links or promotes a verified claim.

Sequential observations are not an atomic distributed permission/expiry fence. Policy/source changes after the last owning observation can stale the response. This is authenticated in-process SDK composition, not network transport, deployment identity proofing or a signed attestation. It validates source metadata and representation anchors, not original bytes/decryption/current malware scanning/extraction truth/consent/rights, legal/editorial approval, work completion or action permits.
